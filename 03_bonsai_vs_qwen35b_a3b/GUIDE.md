# Bonsai 27B versus Qwen3.6 35B-A3B on a GTX 1070

This is an executable, chapter-aligned handoff for **Can a 3.5GB model replace my 35B daily driver? (Bonsai 27B)**. It was prepared for this host on 2026-07-21. Run commands from this project directory.

## 1. Executive overview

The video compares binary Bonsai 27B, ternary Bonsai 27B, Qwen3.6-35B-A3B, and a Gemma control on an RTX 3060. It tests one-shot landing-page generation, an easy disk-repair agent task, a persistent multi-hop service repair, long-output reliability, generation speed, and total runtime footprint.

This host can reproduce only part of that matrix without violating the runtime constraint:

| Candidate | Artifact | Pinned runtime status | Host expectation |
|---|---:|---|---|
| Binary Bonsai 27B Q1_0 | 3,803,452,480 bytes | `Q1_0` and CUDA kernels are present; load still untested | Expected to fit in 8 GB at 4K based on upstream's 5.2 GB peak claim |
| Ternary Bonsai 27B Q2_0 | 7,165,121,600 bytes | **BLOCKED**: no `GGML_TYPE_Q2_0` in the required build | Upstream reports 8.4 GB at 4K before desktop use, so full offload would also exceed this card |
| Qwen3.6-35B-A3B Q4_K_S | 20,893,015,008 bytes | Verified and previously run by project 01 | Hybrid CPU/GPU placement is required; this is the practical daily-driver control |
| Gemma 4 12B control | Video says about 7 GB | **NOT RUN**: exact repository, revision, filename, and quant are absent | A user artifact may be configured, but cannot be called exact reproduction |

The package does not fabricate the missing SSH harness. `05_run_server_repair_proxy.sh` tests whether models can write a durable repair plan, but it never receives tools and must not be reported as the video's agentic result. The exact easy and hard SSH tests remain `BLOCKED` until the original sandbox, tool schema, and prompts are supplied.

No measured result has been generated by this project. All local result cells are `NOT RUN`.

## 2. Source handling

### Local primary evidence

`03_bonsai_vs_qwen35b_a3b.txt` and `description.txt` establish the video's order and reported observations:

- Binary Bonsai is described as a 3.5 GB `Q1_0` model with weights constrained to `-1/+1`; ternary is a 7 GB `Q2_0` model with `-1/0/+1` weights.
- Qwen3.6-35B-A3B Q4 is the 21 GB daily driver, with about 3B active parameters per token and 26 layers in system RAM on the video host.
- All compared models reportedly used the same sampling, KV-cache quantization, effort level, prompts, and reset server environments, but the values are omitted.
- Reported generation rates at an unspecified realistic context are Qwen 48 tok/s, binary 35 tok/s, and ternary 22 tok/s.
- Reported total footprints are 21 GB for Qwen, 5.3 GB for binary, and under 9 GB for ternary.
- The landing pages all met structural constraints; Qwen and ternary were the preferred visual tier. Ternary repeatedly stalled in a long SVG block and needed a nudge in the shown run.
- Every local model reportedly passed the easy disk task after prompt tightening. Binary's earlier loose-prompt run incorrectly reported reclaimed space by about 14x.
- Qwen, ternary, and binary reportedly passed the persistent service task 3/3. Gemma repeatedly entered a valid-tool-call decision loop and was not reliable.
- Binary's worst hard-task run blanked a template and attempted to kill real host processes; sandbox permissions prevented that action.

These are video reports, not observations on this machine.

### External verification

Official model repositories and upstream metadata were checked on 2026-07-21:

- Binary repository revision: `f10afb355f104535e3e3e98cf7ab7795c72bd292`.
- Binary file: `Bonsai-27B-Q1_0.gguf`, 3,803,452,480 bytes, SHA-256 `17ef842e47450caeb8eaa3ebfbbab5d2f2278b62b79be107985fb69a2f819aa0`.
- Ternary repository revision: `abbae723028d71be674e71e1a71201a6f43fab22`.
- Ternary file: `Ternary-Bonsai-27B-Q2_0.gguf`, 7,165,121,600 bytes, SHA-256 `868c11714cf8fe47f5ec9eeb2be0ab1a337112886f92ee0ede6b855c4fa31757`.
- PrismML currently recommends temperature `0.7`, top-p `0.95`, and top-k `20`; those externally verified values are the package defaults because the video's values are missing.
- PrismML currently reports 4K peaks of 5.2 GB binary and 8.4 GB ternary without KV compression. These are upstream measurements, not host results.
- Current model cards call the binary representation 1.125 bits/weight and ternary 1.71 ideal bits/weight, while the shipped ternary slots occupy 2.125 bits/weight. This clarifies why representation size and deployed file size differ.

### Inferences and adaptations

- The landing-page brief is reconstructed from the stated constraints; the verbatim prompt was not published.
- `q8_0/q8_0` is used as a conservative equal KV-cache setting. The video's equal type is unknown.
- Thinking is disabled by default so generated HTML can be validated directly. The video's “effort level” is unknown.
- Project 01's measured `--n-cpu-moe 35` placement is reused for Qwen. Bonsai is dense and does not use that MoE option.
- `llama-bench` uses `pp512` and `tg128`, matching PrismML's current published convention, not the video's undisclosed speed workload.
- The repair proxy is an intentionally weaker diagnostic. It cannot validate tool selection, command count, environment interaction, or restart persistence.

## 8. Final recommended configurations
